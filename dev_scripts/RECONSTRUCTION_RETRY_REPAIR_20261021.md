# Reconstruction retry bookkeeping repair — 2026-10-21

## Scope and causal evidence

This changes only `Decompiler.correct_segmentation` and `correct_failures`, not model weights, tokenizers, datasets, equivalence criteria, or benchmark denominators.

Rejected segmentation candidates left their translated statement lists behind while restoring source lines. Subsequent retries could therefore reconstruct another code object against inconsistent statement/line indices. Separately, equivalence results can contain generated extra bytecode objects, so result-list positions are not original code-object indices.

The repair restores translations along with source state on rejection, matches a candidate's verification result to its original code object, and schedules failed-original retries by original-object identity rather than by verification-result position. Extra generated bytecode remains a verification failure; it is never silently accepted or dropped.

Seven focused regression tests fail against the original methods and pass against the isolated proposed methods. The deployed-source full regression suite passes all 75 tests. Real GPU original/prototype replay reproduced nine distinct bookkeeping crashes and completed all nine after the isolated repair. Completion here does **not** mean bytecode equivalence passed. A tenth case, `formats.pyc`, encountered an independent control-flow `NetworkXError` before error correction with both variants; that failure remains visible and is not claimed fixed.

The final real-GPU check of the deployed source passed all nine causally proven bookkeeping cases. The tenth case retained its independent control-flow failure. The deployed check used no monkeypatches; its report and all original/prototype reports are recorded under the experiment workspace.
